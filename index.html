麻布十番ループル治療院 — HTTPS化 手順書

作成日: 2026-06-15 / 対象: http://www.loople.jp/

0. 現状（確認済み）

  • レスポンスヘッダー server: AmazonS3。Amazon S3 から直接HTTP配信されている。
  • CloudFront（CDN）を経由していない（キャッシュ系ヘッダーなし）。
  • https://www.loople.jp/ は接続不可（証明書がないためエラー）。

重要: S3の静的ウェブサイトホスティングは、それ単体では HTTPS（独自ドメインのSSL）に対応していません。 HTTPS化するには、S3の前に CloudFront（CDN）＋ ACM（無料SSL証明書） を置く構成にするのが標準的な解決策です。 ※AWSの作業になるため、AWSアカウントを管理している制作会社／インフラ担当者に依頼するのが確実です。

1. 全体構成（移行後の姿）

利用者 ──https──▶ CloudFront（SSL証明書をここに設置／HTTP→HTTPS自動リダイレクト）──▶ S3バケット（既存のHTMLファイル）
                         ▲
                      ACM（無料SSL証明書）
DNS: www.loople.jp / loople.jp ──▶ CloudFront

既存のS3のファイルはそのまま使えます。配信経路を変えるイメージです。

2. 手順

STEP 1. SSL証明書を取得（ACM）

  • AWS Certificate Manager で証明書をリクエスト。
  • リージョンは必ず「米国東部（バージニア北部）us-east-1」で発行する（CloudFront用の証明書はus-east-1必須）。
  • ドメインは www.loople.jp と loople.jp の両方を登録（apexドメインも将来使うため）。
  • 検証方法は DNS検証（推奨）。表示されたCNAMEレコードをDNSに追加すると自動承認。料金は無料。

STEP 2. CloudFrontディストリビューションを作成

  • オリジン: 既存のS3バケット（静的ウェブサイトエンドポイント）。
  • Viewer protocol policy: 「Redirect HTTP to HTTPS」（←これでHTTP→HTTPS自動リダイレクトになる）。
  • 代替ドメイン名（CNAMEs）: www.loople.jp（必要なら loople.jp も）。
  • SSL証明書: STEP 1 で発行した ACM 証明書を選択。
  • デフォルトルートオブジェクト: index.html。

STEP 3. DNSをCloudFrontに向ける

  • DNS管理画面（Route 53 など）で、www.loople.jp を CloudFrontのドメイン（xxxx.cloudfront.net）に向ける。
  • Route 53 なら Aliasレコード、他社DNSなら CNAME。
  • loople.jp（wwwなし）も使うなら、wwwへリダイレクトする設定を併せて行う。

STEP 4. サイト内の混在コンテンツを解消（ここが見落としやすい）

HTTPSページの中に http:// のリンクや画像があると「混在コンテンツ」警告で鍵マークが出ません。 - HTML内の自サイト参照を http://www.loople.jp/... → https://www.loople.jp/... に置換。 - 外部読み込み（TripAdvisor・Carecle・GA/GTM・Facebook・Twitter・Typekit等）が http:// の場合は https:// に。 - 迷う場合はプロトコル相対（//...）でも可。 - 先に作成した JSON-LD・OGPタグ内のURLも https:// に統一。

STEP 5. 確認

  • https://www.loople.jp/ が鍵マーク付きで表示される。
  • http://www.loople.jp/ にアクセスすると httpsへ自動リダイレクトされる。
  • ブラウザの開発者ツール（Console / Security）で混在コンテンツ警告が出ない。
  • SSL Labs でA以上を確認。

3. 移行後にやるSEO作業（重要）

HTTPSは「URLが変わる」のと同じ扱いです。以下をセットで行うと評価を引き継げます。

  1. Google Search Console に https://www.loople.jp/ のプロパティを追加。
  2. sitemap.xml を https のURLで作り直し、Search Consoleに再送信。
  3. 各ページの canonical / OGP / 構造化データのURLを https に統一。
  4. GoogleビジネスプロフィールやSNS・各種ポータルに登録したサイトURLを https に更新。
  5. リダイレクトが安定して動いていることを確認後、必要なら HSTS を有効化（最初から入れない。リダイレクト確認後に）。

4. 補足

  • 費用: ACM証明書は無料。CloudFrontは従量課金だが、この規模のサイトなら月数十円〜数百円程度（無料枠もあり）。
  • ダウンタイム: DNS切替時に多少の反映待ち（数分〜最大48時間）があるため、アクセスの少ない時間帯の作業を推奨。
  • AWSを使わない選択肢: どうしてもAWS運用が難しい場合、HTTPSが標準で付くホスティング（独自ドメイン＋SSL自動対応のサービス）へサイトを引っ越す方法もあります。ただし現状の資産がS3にあるため、CloudFront追加が最小工数です。

このHTTPS化が、診断で最優先に挙げた項目です。個人情報・医療情報を扱うフォーム／問診票があるため、 信頼性・コンプライアンス・SEOのすべてに直結します。

3. 口コミ評価（AggregateRating）について ※要注意

口コミ資産は強みですが、AggregateRating の実装には Google のポリシー上の制約があります。

  • Google・TripAdvisor・Carecle など第三者サイトの評価を自社サイトの構造化データに転記すると、ガイドライン違反（手動対策の対象）になる恐れがあります。リッチリザルトに表示されないだけでなく、ペナルティのリスクがあります。
  • 安全に星評価を出すには、自院サイト上で自前で集めた口コミを、ページ上にも実際に表示したうえでマークアップする必要があります。

そのため、まずは上記の店舗情報（LocalBusiness）のみを設置することを推奨します。 自社収集の口コミを表示する運用に切り替えた場合のみ、下記を LocalBusiness 内に追加できます（数値は実データに必ず一致させること）。

"aggregateRating": {
  "@type": "AggregateRating",
  "ratingValue": "【実際の平均評価】",
  "reviewCount": "【自社収集の件数】",
  "bestRating": "5",
  "worstRating": "1"

麻布十番ループル治療院 — 見出し階層（h1→h2→h3）ガイド

作成日: 2026-06-15 / 更新: v2（母数データ反映） / 対象: http://www.loople.jp/（静的HTMLサイト）

母数反映ポイント（v2）: h1・h2に需要の大きい「鍼灸・マッサージ」を優先。母数のある「美容鍼」ページの見出し例を追加（末尾）。

1. ルール

見出しは「文書の目次（アウトライン）」です。検索エンジンはこの階層でページ構造を理解します。

  • h1 = ページの主題（1つだけ）
  • h2 = h1の中の大きな区切り（章）
  • h3 = h2の中の小区切り（節）
  • 段階を飛ばさない（h2の次にいきなりh4は不可）。深さは h3 までで十分。
  • 見た目の大小は CSS で調整。装飾目的でタグを選ばない。

正しい階層のイメージ:

h1（ページの主題）
├─ h2（章A）
│   ├─ h3（節A-1）
│   └─ h3（節A-2）
├─ h2（章B）
└─ h2（章C）

2. トップページの現状（サイト本体のみ）
